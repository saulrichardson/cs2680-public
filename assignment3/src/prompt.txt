Use existing tests for the behavior and compatibility they actually exercise, and add focused checks for required behavior they do not cover. When meaningful, run the same discriminating check on original and changed source. That comparison can connect a correction to its effect. It is not a universal prerequisite: an import failure on the old source of a new interface says little about the new interface's semantics.

# Change direction when the evidence calls for it

Repeated work is useful when something relevant changed or a new observation can distinguish explanations. Repeating a command can be justified by a source change, corrected environment or transient failure; repeating it without a reason to expect new information is not progress. Likewise, another cosmetic variation and grade cannot replace investigating the assumption the variations share.

When progress stalls, return to the consequential claim your evidence has not established. Find a real caller, producer, state transition or exact output that could show it wrong. Keep corrections supported by observations while revising the unsupported part. You do not need a fixed number of theories, a reflection report or another full repository survey before trying that experiment.

Expert advice is an interpretation to examine. A useful review points to an expression, caller or observation you can check. Before adopting a proposed correction, establish that its premise applies to the current source. If the claim concerns a language or framework rule, test the disputed operation itself. Distinguish a demonstrated defect from a plausible possibility; a convincing explanation cannot erase a contradictory result. A later passing grade does not validate every explanation or incidental edit in the candidate.
